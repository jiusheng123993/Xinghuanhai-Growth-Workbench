## 零、提示词工程方法论

### 0.1 Seedance 2.0 通用公式（核心）

```
[主体] + [动作] + [镜头运动] + [场景+光影+天气] + [风格/导演参考] + [物理真实感] + [音频描述] + [时长]
```

**模板骨架**：
```
[精准主体与可见外貌] + [动作细节与相对节奏] + [单一镜头运镜] + [场景环境] + [光影色调] + [目标视觉风格] + [写实/目标画质] + [连续性与排除约束]；音效意图用 <> 标记，旁白/字幕/BGM 后期处理。
```

### 0.1.1 Seedance 2.5 工程型公式（星河宠记当前执行标准）

```
[精准主体] + [动作细节] + [场景环境] + [光影色调] + [镜头运镜] + [视觉风格] + [画质] + [约束条件]
```

- **生成前先看图**：逐张提取可见主体、外貌、姿态、互动、场景、构图和光线，并与 `photo_index` 一一对应；识别失败只保守保持原图，不编造。
- **宠物名字绝不进入视频生成字段**：名字可出现在标题、旁白、字幕，但不得进入 `anchors.desc`、`identity_anchor` 或 `seedance_prompt`；历史脚本重试时也要再次清洗。
- **首帧必须显式锁定**：图生视频输入设置 `role: first_frame`；默认保持参考首帧原始朝向，不强制左右镜像。
- **静图只做低缓微动作**：每镜一种运镜；缓慢眨眼、轻微呼吸、耳朵/尾巴尖小幅动作，禁止凭空奔跑、跳跃、转身。
- **画质与排除同时写**：写实照片级质感、电影质感、色彩自然、细节丰富；排除黑白、手绘、插画、动画、塑料CG、文字、字幕、logo、水印。
- **连续性五锁**：COUNT / SCREEN DIRECTION / IDENTITY / ANATOMY / QUALITY，分别锁数量方向、身份外貌、身体结构和画面稳定性。
- **记忆锚定（防编造，2026-09-01 新增）**：分镜叙事（SCENE 事件、旁白、字幕）只能以三类真实素材为事实来源——记忆引擎摘要（`agent_memories` 核心层 + 时光线 `pet_moments` 回忆文本）、用户亲述文案（`source_text`）、逐张照片视觉摘要。素材中出现的具体回忆必须优先写进对应分镜旁白；素材完全为空时禁止虚构具体事件、日期、对话与人物关系，只允许照片可见事实与中性通用氛围（光线、季节感、陪伴感）。照片可见事实与记忆文本冲突时以照片为准（照片是首帧权威）。

### 0.1.2 v5.1 全库调用协议（169 张卡片统一继承）

> 本协议解决“方法论升级了、后面旧卡片却没逐条复制五锁”的问题。卡片正文只负责表达差异化画面，调用时必须按其模式拼接统一尾缀。**禁止只复制卡片正文直接请求模型。**

#### 模式 S：首帧安全模式（真实宠物照片默认）

适用：纪念 Vlog 中含真实宠物的镜头、B/D 类中与真实照片姿态一致的卡片、第三章日常静图动效。

```text
参考<图片1>中的宠物作为唯一身份与首帧，严格保持原图中的毛色、花纹、体型、五官、年龄特征、身体姿态、在场主体数量、场景、道具、构图、光线方向和原始朝向。
{卡片差异化场景正文；若与照片冲突，以照片为准}
镜头只使用一种运镜；主体仅做与原姿态连续的低缓微动作：缓慢眨眼、轻微呼吸、耳朵轻转、胡须或尾巴尖小幅摆动。禁止凭空奔跑、跳跃、翻滚、转身或增加互动。
写实照片级质感，电影质感，色彩自然，细节丰富；避免生成任何文字或字幕、logo、水印。
COUNT LOCK：画面只出现照片中已有的宠物与人，不出现额外动物、人物，无镜面/玻璃倒影出现第二个。
SCREEN DIRECTION：保持参考照片首帧中的原始朝向与屏幕运动方向，不左右翻转，不在镜头中途换向。
IDENTITY LOCK：保持每个主体的毛色、花纹、体型、五官与参考图一致，色彩按主色/辅色/强调色三层占比复现、比例不得互换或额外加色；细节密度与纹理量级对齐参考图，不额外堆砌花纹或配饰；无 logo、无可读文字、无水印，避免生成任何文字或字幕。
ANATOMY LOCK：身体结构自然，四肢数量正确，无肢体畸形、额外肢体、脸部扭曲、主体复制或穿模。
QUALITY LOCK：高质量，细节丰富，电影质感，色彩自然，动作低缓连续，焦点稳定，无闪烁、抖动或形象漂移。
AUDIO：无人物对白、无模型字幕、无模型BGM；旁白、字幕、BGM与环境声由后期统一混合。
```

> ⚠️ **以上 5 把锁的权威原文以代码为准**：`03-源代码/server/src/services/promptTemplates.ts` 的 `appendLocks()`。
> 本块已与代码逐字对齐（2026-09-19 收敛，此前文档写「不改变年龄或外貌」而代码无此项、代码多文字/水印禁令，
> 属两套文案漂移）。**改代码必须同步改此处**；`promptTemplates.test.ts` 有「锁条数与锁名齐全」断言兜底。

#### 模式 C：创意参考模式（允许重建场景，不直接套真实首帧）

适用：C 类奔跑/跳跃等大动作、13 种风格化卡片、超现实/变形/转绘场景。先用角色设定图或专用关键帧生成场景图，再做图生视频；不得把一张静卧照片直接变成奔跑、飞行或跨风格变形。

```text
将<图片1>中的宠物定义为主体1，只参考其毛色、花纹、体型、五官与特殊标记；不要复制图片1的背景、构图和动作。
{卡片差异化创意正文}
主体1全片保持同一身份、数量和身体结构；一个镜头只使用一种核心运镜，动作写清起始姿态、速度、幅度与自然过渡。
{目标视觉风格}，高质量，细节丰富，画面稳定；无可读文字、字幕、logo、水印，无额外主体、身份漂移、肢体畸形或穿模。
AUDIO：只写所需环境音/音效的设计意图；人物对白、旁白、字幕和BGM默认后期制作。
```

#### 模式 P：后期模块（不单独生成宠物主体）

适用：A/E 空镜、F 转场、G 光影调色、H 音频、Shot 6 字幕落版。此类模块只处理环境、转场、调色、音频或字幕，不负责重建宠物身份；需要文字时由 ASS/剪辑后期添加，禁止要求视频模型生成可读文字。

```text
{卡片差异化模块正文}
不新增、替换或重建宠物与人物，不改变前后镜头已有身份、构图轴线和色彩连续性。
所有标题、宠物名字、日期与金句由后期字幕层添加，视频模型不生成任何可读文字、logo或水印。
```

### 0.2 五大黄金法则

| 法则 | 说明 | 示例 |
|------|------|------|
| **前20词决定80%质量** | 主体+动作放最前面 | 先写“同一只参考宠物，明确毛色花纹与可见动作”，再写风格 |
| **甜区50-120词** | 太短缺乏细节，太长后半段被忽略 | 控制在中等长度 |
| **具体 > 模糊** | 写品牌/风格名代替形容词 | 写"Kodak Portra 400"而非"vintage" |
| **动作描述 > 情绪标签** | 写"tear rolling down cheek"而非"sad" | AI理解动作比情绪更准 |
| **一个镜头一个运镜** | 每次只加1个核心运镜词 | 不要同时写dolly+pan+tilt |

#### 0.3.1 多角度参考包升级版（2026-08 最新做法，全平台通用）

> 来源：MiniMax H3 Omni Reference 官方指南 / invideo 多角度角色卡教程（2026-07）/ lxe/skythread R2V 实战（2026-08-05）。

每个角色先做一套多角度参考包，一次做好、反复用：

```text
正面肖像 → 锁脸、发型、年龄、身份
3/4 侧面 → 锁面部立体度
全身照   → 锁服装、鞋、体型比例、道具
面部特写 → 锁五官细节（可选）
```

规则：
- 生成之间不换参考图，否则等于没锁。
- 同一套图不能自相矛盾（图1短发、图2长发会被模型平均化）。
- 多角色时，脸最正的图放最前，提示词按 `<Picture 1>`、`<Picture 2>` 顺序引用。
- 每张图只分配一个职责，用 "only / do not copy" 防串扰：
  `Image 1 锁脸，Image 2 锁服装，Image 3 只锁场景光线，不得迁移任何面部或服装特征。`
- 场景单独做"空镜参考卡"，只锁环境/光线，不锁人物。

### 0.5 MiniMax H3 提示词结构（新增）

#### I2VA（图生视频，首帧/参考图锁定）

```text
<音乐风格、进入点、情绪>

```

#### R2V（参考驱动，多图锁角色 · 官方六段式）

```text
subject_definitions: 定义被引用内容与标签(<Subject 1> / <Picture N> / <Video N> / <Audio N>)
summary: 任务类型、目标视频、主要引用关系
retention_analysis: 引用内容如何保留/迁移/复用
detailed_description: 按播放顺序写画面、动作、镜头、声音、对白
overall_soundscape: 环境声与物理音效
non_diegetic_music: 背景音乐
```

本地部署说明：ComfyUI 的 `MiniMaxH3ReferenceToVideo` 节点，`ref_images` 支持最多 9 张
参考图（另有参考视频/音频）；R2V 使用独立权重 `minimax_h3_ref2va_pruned_int8_convrot.safetensors`
（约 19.5G，与 I2V 的 fl2va 权重不通用）。参考图按连接顺序用 `<Picture 1>` 引用。

### 0.6 全局角色锁定表（必建，先于一切提示词）

```markdown
## 全局角色锁定表（每幕必须遵守）
- 角色A：身份+年龄+五官+发型+体型+服装+配饰+道具，写死。允许变化：表情、视线、姿势、呼吸。
- 数量敏感角色（如"外婆"）：显式声明"全片只能出现这一个"。
- 易跑偏角色（如"猎人"）：显式排除兽化特征"绝对的人类，没有兽耳/獠牙/尾巴/毛皮，不是狼人"。

## 每幕声明
- 在场人物：<写死>
- 禁止人物：<写死，防模型加戏>
```

宠物回忆录实例：

```text
- 宠物：成年金毛，金黄色卷毛，胸口白色斑块，戴红色皮质项圈+铜铃铛。全片同一只，毛色体型不变。
- 主人：35岁东亚女性，齐肩黑发，米色针织开衫，浅蓝牛仔裤。全片同一人。
- 禁止：第二只宠物、宠物变种/换毛色、主人换人、画面文字、水印。
```

### 0.7 负面约束清单（H3 适用；Seedance 用正向表达）

```text
禁止出现：第二个<角色>、角色身份互换、角色融合、多手多脚/畸形肢体、
狼人/半兽人/兽耳人类、多余路人、数量不符、画面文字/字幕乱码、水印、
镜头抖动、硬切、浮空部件。
```

注意：Seedance 2.0 不支持负面提示词（见第八节避坑表），该平台继续用正向写法；
H3 在 prompt 内直接写"禁止出现……"有效，且几乎每条高质量 H3 提示词都带负面约束。

### 0.8 跨模型一致性：配方卡 + 回归测试

同提示词在不同模型上结果必然不同（提示词不可移植），靠 5 层兜住：

1. 提示词只写"模型无关"的控制点：客观可验证描述（金色晨光丁达尔光、暮色蓝调、低机位缓慢推近），少用"电影感/高级感"空词。
2. 参考图优先：角色参考包锁身份，提示词只管动作。
3. 固定配方：模型文件+LoRA+采样器+步数+seed+分辨率+帧数，每次记录配方卡。
4. 换模型前回归测试：同一参考图+锁定提示词，新旧模型各出一段逐项对比（角色/数量/运镜）。
5. 视觉校验兜底：DeepSeek 多模态逐张检查"角色构成、数量、有无畸形"，不过就重生成。

配方卡模板（随交付文档保存）：

```markdown
## 生成配方卡
- 模型：minimax_h3_ref2va_pruned_int8_convrot.safetensors + turbo LoRA(1.0)
- 参数：8步，864×480，124帧(5秒)，seed=xxx
- 参考图：<文件名>（职责：锁脸/锁服装/锁场景）
- 提示词：见对应分镜
```

### 0.9 细节描写清单（眼神/身体动作/逐秒拆解）

> 用户要求："提示词要每一个细节都描写,具体到眼神、身体动作。"

| Lock | 作用 | 示例 |
| --- | --- | --- |
| COUNT LOCK | 数量锁定 | “画面只出现照片中已有的宠物与人，不出现额外动物、人物，无镜面/玻璃倒影出现第二个” |
| SCREEN DIRECTION | 方向轴 | “保持参考照片首帧中的原始朝向与屏幕运动方向，不左右翻转，不在镜头中途换向” |

### 0.12 多角色锚点（多宠物/多人，2026-08 新增，代码已实现）

> 4 猫 2 人家庭场景：每个在场角色一个锚点，全片逐镜逐字重复。
> 人物用稳定特征（发型/服装/体型），不用表情；每镜只声明本镜在场角色（characters_present）。

```jsonc
"anchors": [
  { "id": "doubao", "type": "pet", "desc": "橘色短毛猫，白色胸脯，右耳缺一角" },
  { "id": "mama", "type": "human", "desc": "女性，长发，米色毛衣" }
],
"segments": [{
  "characters_present": ["doubao"],   // 本镜只有猫在场
  "seedance_prompt": "……CHARACTERS 段只注入 doubao 锚点……"
}]
```


**逐秒模板**：

```text
[镜头N] 0-5s,<景别>。
0-1s: <角色A>眼神/手/身体在做什么; <角色B>……
1-2s: <状态变化,触发动作>
2-3s: <关键动作,表情转折>
3-4s: <眼神/手部细节>
4-5s: <收束落点,镜头动作>
```

每段写"谁+眼睛/手/身体+做什么",避免只有情绪词；音频也按触发秒数写。

**角色全貌锁定（从头发到脚趾）**：每个角色写一段完整外观,按顺序:
头发(颜色/编法/发饰)→额头→眉毛→眼睛(颜色/形状/睫毛)→鼻子→嘴→下巴→脸颊→
耳朵→脖子→领口→上衣(领型/扣子/口袋/袖长)→腰身→裙/裤→手(指形/饰品)→腿→
鞋(靴筒/鞋带/鞋头)→随身道具。写进 subject_definitions 或独立的
character_appearance_lock 段,每幕对在场角色重复注入,并加"形象与参考图完全
一致,不得改变任何外观细节"。

```text
主体1：{品种/物种}，{毛色/花纹}，{体型}，{眼睛/鼻子/耳朵}，{特殊标记}，{年龄阶段}。

角色锚点：全片逐镜重复主体1的外貌事实，不写宠物名字。
身份锁：毛色、花纹、体型、五官、年龄特征与参考图一致；不换品种、不变脸、不增减主体。
数量锁：只出现照片中已有的宠物与人，不出现额外主体、镜面复制或无依据互动。
解剖锁：身体结构自然，四肢数量正确，无额外肢体、脸部扭曲、穿模。
```

## 八、避坑清单

| 错误写法 | 正确写法 | 原因 |
|----------|----------|------|
| `beautiful, amazing, stunning` | `Terrence Malick style, golden hour, 8k ultra detailed` | 模糊形容词AI无法理解 |
| `she is very sad` | `tear rolling down cheek, trembling lip, slow motion 60fps` | 用动作描述代替情绪标签 |
| `a girl` | `25-year-old Asian woman, long black hair, cream sweater` | 主体必须具体描述 |
| 一次写5个运镜 | 每次只写1个核心运镜 | 多运镜会让AI混乱 |
| 提示词超过150词 | 控制在50-120词 | 后半段权重极低 |
| `not ugly, not blurry` | `sharp focus, clear details` | Seedance不支持negative prompt |
| 语言固定英文 | 中文主体事实 + 必要英文摄影术语 | 语言以模型实测为准，不能牺牲主体、外貌和约束的可读性 |
| 参考图职责不清 | 首帧图用“参考图片1/首帧”，角色设定图只锁外貌 | 混用会造成背景与动作串扰 |
| 通篇悲伤无出口 | 悲伤后必有释怀场景 | 用户体验需要情绪释放 |
| 角色没写死（猎人变狼人） | 全局角色锁定表 + 每幕"在场/禁止人物" | 身份、数量、兽化特征必须显式排除 |
| 参考图职责不清 | 每张参考图只分配一个职责 + "only / do not copy" | 多图混用会导致特征串扰 |
| 换模型后角色漂移 | 配方卡 + 一致性回归测试 | 同提示词≠同结果，模型间不可移植 |

## 十三、运镜四要素公式与选型原则

> **素材出处**：报告 `2号-A04-运镜与分镜.md` §五·5-7；
> 原资料包文件 `[md] 4-小说漫剧提示词\AI漫剧16个运镜提示词模板.md`。

**四要素公式**：`运镜类型 + 核心参数 + 场景适配 + 风格要求`
（原句：`精准的运镜提示词需包含「运镜类型+核心参数+场景适配+风格要求」四大核心要素，避免模糊表述。`）

**核心参数 = 5 类**（写运镜时逐项填满）：运镜速度（慢推 / 快推、缓移 / 急移）· 镜头焦距（广角 / 长焦 / 标准）· 取景范围（全景 / 中景 / 近景 / 特写）· 焦点控制（跟焦 / 定焦）· 画面效果（稳定 / 抖动 / 模糊渐变）

**正例（照抄，再换掉风格后缀即可用）**

```
【慢推+标准焦距+近景+跟焦主角面部+稳定画面+日系动漫风格】
```
→ 宠物版：`【慢推+标准焦距+近景+跟焦宠物面部+稳定画面+写实照片级质感】`
（去掉 `日系动漫风格` —— 二次元是我们明确排除的方向）

**选型原则（照抄）**：`基础运镜应作为主流，复杂运镜仅用于关键场景的强化表达。`
→ 与我们的"**每镜一种运镜**"红线同向，可作为该红线的外部佐证。

**写作校验清单**（2号 §五·15）：① 避免矛盾指令（不要同时要"极简风格"和"丰富细节"）；② 不要过度堆砌关键词（精选核心要素）。
⚠️ 原清单的"精选 3-5 个"与我们 `0.2 甜区 50-120 词`并存时，**以我们的词数纪律为准**，把"3-5 个"理解为"**核心要素不许重复堆**"。

| **技术要点** | 制作时需要注意的技术细节（把踩坑点挂在**单镜**上） |

**其中三项我们完全没有**（`6号` §6.3 判定）：

- `用途` —— 给每个镜头标注**叙事职能**，用来防"镜头堆砌"；
- `技术要点` —— 把**生成阶段的踩坑点挂在单镜**上；
- **镜头级 `光线：[来源、强度、色温]`** —— 把布光**下沉到逐镜**（我们目前是全局布光，只在 `LIGHTING` 段写一次）。

⚠️ **落地提醒**：`情绪氛围` 与 `台词·旁白` 两组的"情绪"字样与我们的 **Anti-Subjective** 冲突 ——
在本库内部使用这套 schema 时，**只取其槽位结构**，内容一律改写为视觉事实句（见 §十六 铁律）；
台词 / 旁白 / 字幕由**后期字幕层**承担，不要求视频模型生成任何可读文字。

## 十五、神兽卡（A12）可直接迁移的四条"形式"

> **素材出处**：报告 `4号-A01动物线+A12神兽卡.md` §六·1-5 与 §三（压缩策略）；
> 原资料包文件 `【A12】第01份_001-010.txt`、`【A12】第03份_021-030.txt`（全 20 份 × 10 只 = 200 只逐份实测）。

**背景**：神兽卡单只平均约 1900 字符，其中近半数是"多视图资产设定图"的样板文字 ——
**我们做的是图生视频，那部分一律不进 prompt**。真正值得学的是它**四个"量化 / 基准"的动作（形式）**，不是它写的那些数字。

⚠️ **铁律：神兽卡的具体数值一个都不要抄。**
百分比、华丽度分数、净色区比例等，在原资料包的 200 只里**近乎逐条相同**（属模板常量），照抄等于往 prompt 里加噪音。
**要学的是"有没有量化"这个动作；数值一律从用户真实照片取样。**

| 形式 | 写法模板（数值留空，从真实照片取样） | 出处 |
|---|---|---|
| ① **色彩三元占比结构** | `主色{…}约占{…}，辅色{…}约占{…}，眼周与耳内强调色{…}约占{…}；参考图1已明确的毛色优先且保持不变` —— 对我们是**真量化**（毛色占比是能从照片里数出来的真事实） | 4号 §六·1 / §2.3（改写自 `【A12】第01份_001-010.txt` 白虎条） |
| ② **纹理密度量化（四层递进 + 净色呼吸区）** | `采用{…}层递进的源生纹理，并保留一块净色呼吸区（比例从真实照片取样）` —— 作用是**防 AI 把整张图堆满纹理导致毛发糊成一团**；⚠️ "四层 / 五级轮廓层"这种层级计数属虚构生物的装饰需求，**宠物不适用** | 4号 §六·2 / §2.4（`【A12】第03份_021-030.txt` 腓腓条【材质与纹样】） |
| ③ **参考图当"量级基准"** | `细节密度对齐参考图N` —— **不是**让模型抄图 N 的内容，而是把图 N 当作"复杂到什么程度"的**标尺**；用户上传了精修写真 / 影棚照时最好用（比写"高清"有效） | 4号 §六·4 / §2.5 |
| ④ **多视图"数量不固定，选最少且足够"** | `视图数量按该宠物的体型、长度与肢体结构选择最少且足够的角度` —— 我们的参考图包按实情定 2~4 张即可，不必强凑三视图 | 4号 §2.6（`【A12】第03份_021-030.txt`【多视图布局】变体） |

**另两条可直接补进"锁"的措辞**（4号 §六·3 / §六·5 / §2.6）：

- **回指式解剖声明**：`严格锁定本条声明的解剖数量，不增加、不缺失、不融合任何头部、眼睛、肢体、尾巴`
  —— 比现有 `ANATOMY LOCK` 的"四肢数量正确"更硬（**要求回指本条声明**，且列举更宽，含头 / 眼 / 尾）。
- **镜像花纹锁**：`不出现意外增生、缺失、融合、错位或镜像花纹变化`
  —— 对**左右不对称**的宠物（单边花纹、单耳缺角、异色眼）真有用；AI 在频繁生成里确实会把不对称花纹镜像。
- ⚠️ 宠物版只保留 `头部、眼睛、肢体、尾巴`，**删掉 `翅膀 / 触须 / 体节 / 角`**。

### 16.3 明确不迁移的三类（3号 §七）

> 口径按 `审-1-独立复核.md` §二·V1 / §五·V1 修正。**本节在 2026-09-19 由「已知缺口」改为「已落地」**，
> 历史结论保留在最后一节，避免后来人把旧状态当现状。

### 19.1 现在的实现（代码层已落地）

- **每镜先出关键帧，再图生视频**。新增服务
  `03-源代码/server/src/services/memoirKeyframeService.ts` → `generateMemoirKeyframe()`：
  逐镜用 Seedream 出一张 **16:9 电影质感静帧**，再由 Seedance 以该静帧为首帧生成动效片段。
- **接入点**：`videoGenerationService.ts` 每镜在调 Seedance 前先 `await` 关键帧；
  **成功用关键帧做首帧，失败回落原照片**（关键帧是尽力项，不拖垮整片）。
- **参考图两份**（这是本次同时补上的"残缺"）：
  - **参考图1 = 该镜真实照片** —— 画面依据：姿态取静、构图取准、场景取真、屏幕朝向照旧；
  - **参考图2 = 宠物四视图全身设定图**（`pet_profiles.avatar_multiview_url`，可空）——
    **只核对毛色/花纹/体型比例/五官**，并**显式禁止复制它的分格版式**（设定图是四宫格，不写禁令模型会照抄成拼图）。
  - 说明：该字段与"真实照片 > 设定图 > 卡通头像"的优先级口径**在全家福里早已实现**，
    回忆录链路此前**只传单张真实照片**——本次补齐的是这条链路的接入。

### 19.2 两条配套口径

- **画幅固定 16:9**：常量 `MEMOIR_SEGMENT_RATIO`（原为 `'adaptive'`，跟随照片 ⇒ 每段画幅不一致、拼接观感参差）。
  关键帧尺寸 `1920x1080`（已实测上游接受）与它成对；
  **三方必须一致**：关键帧尺寸 / 提示词画幅声明 / Seedance `ratio`。
- **全链路不做可见角标（2026-09-19 用户决定，已扩大到图片侧）**：回忆录**成片**、**关键帧**、
  以及**图片侧**（全家福 / 头像 / 表情包）**一律不加可见 AI 角标**。
  - 转存管线仍在，只是不加角标：`addAiBadge` 已重命名为 **`hostAiImage`**
    （职责如实描述为「把临时 CDN 图转存本站 + 写隐式元数据」）；角标通道保留为 `{ withBadge: true }`
    的**一行开关**，**当前无任何调用点**打开它。
  - ⚠️ **隐式 AIGC 元数据照旧写入**（PNG `tEXt` AIGC / MP4 `udta`，依据《标识办法》第十条）——
    用户不可见，**不是"水印"**，本轮未削弱。
  - **风险已知**：用户在被明确告知 **2026-04-28 网信部门查处「剪映」「猫箱」「即梦AI」**
    （事由「未有效落实人工智能生成合成内容标识规定要求，违反《网络安全法》」）后做的决定。
    完整留痕见 `项目记忆/progress.md`（2026-09-19「决策留痕」两条）。
  - 若日后需要恢复可见标识：**做成片级/整图级统一烙一次**（位置稳定），不要做成关键帧级，
    也不要下放成用户可关闭的开关。
