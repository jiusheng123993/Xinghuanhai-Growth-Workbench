# 回忆录 2.1 · 切片式生成（两个入口）方案

> 日期：2026-09-11　作者：DSH（起草）　状态：**待用户拍板**（本方案是设计，未动代码）
> 缘起（用户原话）：
> "现在不是做成一条回忆时光的线了吗，那么回忆录就根据这一条就行了。可以让用户通过宠物标签去进行选择要生成回忆录的宠物时光。做两个入口：一个是根据时间去做回忆录，这样就直接从所有回忆录里面截取，不分宠物；第二个入口就是按照宠物标签加时间去截取，做特定宠物的回忆录。"

---

## 0. 一句话

把"回忆录的输入"从**一只宠物**升级为**一个素材切片（时间区间 × 宠物范围）**——于是自然长出两个入口：
**① 按时间做（不分宠物，全家）** 与 **② 按宠物标签 + 时间做（特定宠物）**。

| 项 | 现状 | 结论 |
| --- | --- | --- |

## 2. 核心概念：MemoirSlice（素材切片）

```ts
type MemoirSlice = {
  scope: 'all' | 'pets'          // all = 不分宠物；pets = 按标签
  petIds?: string[]              // scope='pets' 时必填，1..3 只
  preset?: 'last30d' | 'last90d' | 'thisYear' | 'all' | 'custom'
  from?: string                  // 'YYYY-MM-DD'（含）
  to?: string                    // 'YYYY-MM-DD'（含）
}
```

**命中判定（唯一权威口径）**

```
回忆 ∈ 切片  ⟺  date(happened_at ?? created_at) ∈ [from, to]
                且 (scope = 'all'  或  回忆的宠物集合 ∩ petIds ≠ ∅)
```

- 日期用 **`happened_at`（补记日）优先、回退 `created_at`** —— 与时光页展示口径一致（补记支撑）。
- SQL 形态：`pet_id = ANY($1::text[]) OR content->'pets' ?| $1::text[]`（JSONB 数组成员判定）。
- **多宠共同回忆两边都算命中**：一条挂「烧鸡+烧鸭」的回忆，在烧鸡的回忆录和烧鸭的回忆录里都出现（这正是上一轮遗留的那个边界，在这里一并解决 ✅）。

**主宠物约定（只在三个地方用，不参与内容筛选）**

| 用途 | 取值 |
| --- | --- |
| 并发互斥键（`findActiveByPetId`） | `petId = petIds[0]`；scope='all' 时取"最早建档的那只" |
| 历史列表分组 / 路由参数 | 同上 |
| 剧本确认幂等键（`memoir_prompt_confirmations` 按 user+pet+tier） | 同上 |

> 这样**不用动任何现有路由的形状**，`POST /:petId/memoir` 照旧，只是 body 多了 `slice`。

## 3. 两个入口（UI 与交互）

### 入口位置
1. **回忆录馆**（`memoir-center`）顶部加两张大卡：「从时光里挑一段时间」/「给某只毛孩子做」；
2. **时光页**顶部加按钮「把这段时光做成回忆录」→ 直接进入口 A，并**带上当前上下文**（默认 scope=all + preset=last90d）；
3. 保留原有三档卡（作为"我已想好档位"的快捷路径，向下滚动可见）。

### 入口 A · 按时间做（不分宠物）
```
[近 30 天] [近 3 个月] [今年] [全部] [自定义 ▾]
────────────────────────────
命中预览（实时）
  32 条回忆 · 14 张可作首帧的照片 · 涉及 2 只毛孩子
  其中 5 条是两只共同回忆
  建议档位：完整回忆录（8-15 张）  ✓ 素材够
────────────────────────────
[ 下一步：挑片与档位 ]
```
- 时间范围 = 唯一筛选维度；**不出现宠物选择器**（这就是"不分宠物"）。

### 入口 B · 按宠物标签 + 时间
```
记给谁（可多选，最多 3 只）
[🐱 烧鸡 ✓] [🐱 烧鸭] [🐕 布丁]
────────────────────────────
时间范围（同入口 A）
────────────────────────────
命中预览
  烧鸡：18 条回忆 · 9 张照片
  共同回忆（烧鸡+烧鸭）：5 条
  建议档位：标准回忆录
[ 下一步：挑片与档位 ]
```

### 共用确认页（替换现有"手选照片"页的入口部分）
1. **档位**：按可用照片数自动建议 + 不可用档位置灰（沿用现有 `isTierAvailable`）；
2. **自动选片结果**：N 张缩略图（可单张「换一张」、可整段重挑）；
3. **叙事来源**：显示"有描述的回忆 X 条（将进入旁白）"；
4. **标题**：自动生成可改（如「2026 夏 · 烧鸡和烧鸭」）；
5. 价格 / 支付（完全复用现有链路）。

## 4. 自动选片（这是"直接截取"能否成立的关键）

用户不想手挑 15 张；所以切片必须给出一份**默认就够好的选片**：

**分桶采样算法（纯前端可算，也可服务端算）**
1. 取切片内所有"带照片"的回忆，按日期升序；
2. 把区间**均分 N 段**（N = 档位张数上限：3 / 7 / 15）；
3. 每段内优先选「有描述 + 有照片」的回忆（描述质量决定旁白质量）；
4. 多宠场景：同段内优先覆盖不同宠物（避免整条片子只有一只）；
5. 去重：同一条回忆最多取 2 张；相隔 <2 秒/同一相册连拍只留 1 张；
6. 段内不足时向前后段借（保持时间顺序不乱）。

**可换**：单张替换**限定在同一段内**（保住时间分布不被破坏）；也可"整段重挑"。

---

## 5. 素材口径：照片 vs 叙事（两个数都要给用户看）

| 类型 | 作用 | 是否计入档位门槛 |
| --- | --- | --- |
| 有照片的回忆 | **首帧**（Seedance 需要图） | ✅ 计入 |
| 只有文字的回忆 | **旁白/叙事素材**（提升脚本丰富度） | ❌ 不计入 |

预览必须同时给"能选几张"和"有多少故事"，否则会出现"选得出 8 张但没故事"的落差。

## 6. 改动清单（前后端 + 风险）

**服务端**
1. `memoirMaterialService` 新增按切片的查询（`getSlicePreview(userId, slice)`）：返回
   `{ moment_count, moment_photo_count, moment_with_description_count, pet_breakdown[], shared_moment_count, suggested_tier, suggestion_reason, auto_selected_photos[] }`；
2. 新接口 `POST /api/memoir/slice/preview`（`authMiddleware` + 复用 `memoirLimiter`，**只读、不计费**）；
3. `POST /:petId/memoir` 的 `createMemoirSchema` 增加可选 `slice`；
4. 落库：见下（**需要你确认**）。

**数据库（⚠️ 需要你拍板）**
- 推荐：`ALTER TABLE pet_memoir_records ADD COLUMN IF NOT EXISTS slice JSONB` —— **纯新增列、无需回填、旧代码不受影响**（本项目 migrations 已是这个套路）。
- 不加列的退化方案：塞进现有 `narrative_structure(JSONB)` —— 语义混在一起，**不推荐**。

**小程序**
1. 新页面 `pagesMemoir/memoir-slice/index`：入口 A/B 共用一个筛选页（用参数区分），实时预览（防抖调用 preview）；
2. `memoir-center` 加两张大卡；时光页 PageHero 加「做成回忆录」按钮（带上下文）；
3. 现有 `memoir-vlog / memoir-full / memoir-daily` 的**选片步骤**改为"接收预选结果 + 可换一张"，其余（档位/文案/确认/支付）不动；
4. `services/memoirService` 增加 `previewSlice(slice)`。

**不改**：支付、退款闭环、剧本确认闸门、Seedance 适配器、提示词库。

## 7. 边界与降级

| 场景 | 处理 |
| --- | --- |
| 区间内 0 张照片 | **不进退档位页**，给「放宽到近半年 / 改成全部」一键建议 |
| 1-3 张 | 只亮「轻纪念」 |
| 5-7 张 | 亮「轻纪念 + 标准」 |
| 8-15 张 | 三档全亮（沿用现有 `isTierAvailable`） |
| 区间内只有文字回忆 | 允许做"纯图文回忆录"？→ **暂不支持**，提示补照片 |
| 多宠共同回忆 | 两个宠物切片都命中；预览注明"其中 X 条是共同回忆"（避免用户以为重复） |
| 同一素材重复生成 | 允许（用户可能想要不同档位）；历史列表标注切片参数以便区分 |
| 生成失败 | 沿用现有**退款闭环**（脚本失败/放弃自动原路退） |

## 8. 分期建议

| 阶段 | 范围 | 价值 |
| --- | --- | --- |
| **P1（最小可用）** | 切片预览接口 + 筛选页 + **入口 A（按时间·全宠）** + 自动选片预选（仍可手改） | 立刻有"全家回忆录"，不动数据模型的核心 |
| **P2** | **入口 B（宠物标签）** + 多宠共同回忆命中 + 语义预设（生日周 / 纪念日 / 第一次到家） | 补齐"特定宠物"，语义预设是强情绪钩子 |
| **P3** | 多主角回忆录（2-3 只同片）+ 标题/封面自定义 + 历史列表按切片展示 | 差异化卖点 |

## 9. 成本与商业影响

- 素材预览**不计费**（只读查询）；生成才扣费 —— 与现状一致。
- 档位价格不变；**多主角是否加价**见开放问题。
- 最大商业风险：**自动选片质量**。选差了 → 退款/差评。缓解：①预览阶段就让用户看到选片结果并可换；②沿用"剧本确认闸门"（用户确认剧本后才生成视频）；③沿用退款闭环。
